EXECUTIVE ABSTRACT

This report details the architectural specification, formal language design, and front-end engineering for the Zenith programming language compiler. The project focuses on bridging educational clarity with formal compiler construction theory, modeling each canonical phase of language translation: lexical analysis, deterministic parsing, abstract syntax tree generation, hierarchical symbol table scoping, intermediate representation generation, and machine-independent optimization. Phase 1 establishes the foundational design requirements, formal grammar definitions, multi-pass system architecture, and initial prototype verification in accordance with the Phase 1 evaluation rubric.

Chapter 1: Introduction & Motivation

1.1 Background

Compilers form the foundational backbone of computer science and software engineering, translating human-readable high-level programming language representations into machine-executable instructions. The study of compiler construction encompasses formal language grammars, automata theory, syntax-directed translation, lexical scoping models, and intermediate code representations. A classical compiler architecture consists of Front-End analysis, Middle-End intermediate representation, and Back-End target execution.

1.2 Problem Domain & Motivation

Modern software development presents a stark dichotomy: dynamically typed scripting languages defer type and scoping validation until runtime, causing catastrophic failures in production; while large-scale industrial compilers operate as opaque systems where internal abstract syntax trees and intermediate transformations cannot be inspected for academic analysis. The Zenith compiler project addresses this by implementing a strongly-typed procedural language where each compilation phase is strictly decoupled, transparent, and verifiable.

Chapter 2: Problem Statement

To formulate, design, and validate an end-to-end multi-pass compiler system for the Zenith procedural language that:

  • Lexical Analysis: Converts raw source character sequences into classified tokens while tracking line and column position metadata.
  • Syntax Analysis: Parses the token stream using deterministic LL(1) recursive descent parsing governed by an unambiguous formal grammar.
  • Syntax-Directed Translation: Constructs a strongly-typed Abstract Syntax Tree representing program hierarchy free of syntactic punctuation.
  • Scope & Symbol Management: Maintains an active scoped symbol table supporting nested lexical environments and duplicate declaration prevention.
  • Intermediate Code Generation: Translates validated abstract syntax trees into linearized Three-Address Code instructions during subsequent phases.

Chapter 3: Objectives and Scope

3.1 Primary Objectives

  • Specify an unambiguous Context-Free Grammar in Extended Backus-Naur Form (EBNF).
  • Implement a deterministic lexical analyzer with coordinate tracking and comment filtering.
  • Construct an LL(1) Recursive Descent Parser with precedence climbing and panic-mode error recovery.
  • Implement an explicit Abstract Syntax Tree hierarchy with visual inspection capabilities.
  • Develop a Scoped Symbol Table supporting block and function scopes.
  • Deliver a CLI driver and interactive REPL mode for live demonstration.

3.2 Scope Boundaries

The project encompasses core procedural programming primitives including static data types (integer, float, boolean, string, void), mutable and immutable variable bindings, structured control flow (branching and looping), and function declarations with typed signatures. Dynamic heap garbage collection and object-oriented inheritance are formally excluded to maintain strict focus on core compiler pipeline fundamentals.

Chapter 4: Literature Survey & Theoretical Concepts

The design of Zenith is grounded in canonical compiler theory as outlined in Aho, Lam, Sethi, and Ullman (The Dragon Book):

  • Finite Automata: Lexical tokens are recognized through regular expressions mapped conceptually to Deterministic Finite Automata (DFA). A hand-crafted lookahead scanner handles multi-character operators without external dependencies.
  • Top-Down Parsing: LL(1) Recursive Descent parsing is selected over table-driven bottom-up parsing to achieve transparent debugging, precise error localization, and natural alignment with formal grammar productions.
  • Abstract Syntax Trees: ASTs discard grammatical concrete syntax tokens (such as parentheses and semicolons) while retaining exact structural semantics.
  • Scoped Symbol Tables: Lexical scope is represented as a tree of scope environments linked via parent pointers, supporting O(1) insertion and hierarchical lookup.
  • Three-Address Code: Linearized quadruples decouple language-specific grammar from back-end evaluation and target execution.

Chapter 5: System Architecture & Data Flow

The Zenith compiler follows a decoupled multi-pass architecture comprising three principal stages:

  1. Scanner Phase: The Lexical Analyzer transforms the raw character stream into a structured stream of Token objects with coordinate attributes.
  2. Parser Phase: The Recursive Descent Parser applies production rules to validate syntax and produce the hierarchical Abstract Syntax Tree.
  3. Semantic & Scoping Phase: The Symbol Table Builder traverses the AST, populating lexical scopes, registering symbol declarations, and enforcing immutability constraints.
  4. Error Synchronization: Panic-mode recovery seeks statement delimiters (semicolons) and declaration keywords to isolate syntax faults and detect multiple errors.

Chapter 6: Formal Language Specification

The grammar of Zenith is defined formally in Extended Backus-Naur Form (EBNF), ensuring deterministic derivation without left recursion:

  • Program Structure: A program consists of a sequence of top-level statements including variable declarations, function definitions, and control structures.
  • Variable Declarations: Explicit binding keyword ("let" for mutable, "const" for immutable) followed by identifier, type annotation, and optional initializer.
  • Supported Data Types: Primitive types are strictly partitioned into int, float, bool, string, and void.
  • Structured Branching: Conditionals follow deterministic "if-elif-else" constructs with parenthesized boolean conditions and enclosed statement blocks.
  • Iterative Constructs: Supported via "while" condition loops and traditional initialized three-clause "for" loops.
  • Functional Units: Declared with "fn" keyword, typed formal parameter lists, explicit return types, and local body blocks.
